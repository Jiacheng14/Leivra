# Leivra 人物卡 v1

第一版仅支持 Leivra 自有 JSON；不兼容 SillyTavern 世界书、PNG 卡片或第三方扩展格式。

## 使用
联系人操作统一在侧栏「联系人」下：
- 点击头像/名称切换独立聊天，背景与状态圆点标识当前联系人。
- 「添加联系人」选择 Leivra v1 JSON，复用校验后增加联系人并切换会话。
- 每名联系人旁的删除按钮打开确认，列明删除范围；取消或 Escape 不删除任何数据。
- 手机点击聊天标题栏的「打开联系人」按钮，打开同一侧栏；选择或添加成功后收起。

聊天设置 → 人物卡仅保留：
- 导出 JSON：导出当前人物卡，不包含聊天记录和记忆。
- 编辑 → 保存人物卡：修改当前角色，ID 不变，revision 自动加一。

导入人物卡必须使用尚未存在的稳定 ID。重复 ID 不覆盖，也不自动更换 ID；如要新建另一人物，请在 JSON 中改成新 ID。更新已有卡使用编辑入口；暂不提供覆盖导入。
新增人物没有自动生成的欢迎语。旧版蕾芙菈的首次 Mock 示例消息保持兼容，旧聊天及用户清空过的记录不会重复生成。

## 格式
~~~json
{
  "schemaVersion": 1,
  "id": "my-contact",
  "revision": 1,
  "name": "联系人名称",
  "avatar": "/avatar.svg",
  "background": "",
  "personality": [],
  "speakingStyle": "",
  "relationship": "",
  "customPrompt": "",
  "preferences": {
    "temperature": 0.7,
    "maxReplyMessages": 3
  }
}
~~~

除 preferences 外字段必需。空字符串和空性格数组表示未设定；名称与头像不能为空。
名称最多 80 字符；ID 为 1–80 位字母、数字、点、下划线、连字符，以字母或数字开头。
背景最多 8000 字符，语言风格和关系各 4000，自定义提示词 12000；性格最多 20 项，每项 500 字符。
文件与规范化人物卡最多 256 KiB。头像支持站点内图片路径或内嵌 PNG/JPEG/WebP；不加载卡片指定的远程 URL。自定义图片上传界面未实现。

schemaVersion 当前只支持数字 1，其他版本或未知字段明确报错，不做猜测式转换。revision 是正整数；编辑自动增加，不影响稳定 ID。
temperature 可选，范围 0–2，当前适配器暂不发送该参数；maxReplyMessages 可选，范围 1–8，仅保留格式兼容，不再限制自然回复条数。其他偏好参数会报错。人格字段不能修改通用协议或输出格式。
编辑界面保留已有偏好；修改偏好可在导入前编辑 JSON，本阶段未添加参数面板。

## 保存位置与隐私
人物卡、当前联系人、会话和消息存于当前 origin 的 localStorage：leivra.data.v1。它不是项目目录中的数据库文件，也不跨设备或端口同步。
默认人物卡源码在 src/characters/defaultLeivra.ts。修改源码不会覆盖浏览器中已经保存的人物卡，日常修改通过设置完成。
卡片导出与聊天导出分开；聊天导出仅包含当前角色、会话标识和对应消息。
旧数据键 leivra.prototype.messages.v1 在迁移后保留为备份；清空默认角色消息或删除默认联系人时删除此备份。清空其他角色不会影响默认角色与备份。
未加密；清理浏览器站点数据会删除所有联系人和历史。当前不保存长期记忆。

## 删除及空状态
确认删除会先取消未完成的回复，再删除该角色的人物卡、专属会话及消息；默认联系人的旧版聊天迁移备份（如有）也会清理，其他联系人不受影响。
删除当前联系人后切换到列表中第一名剩余联系人；删除非当前联系人保持当前选择。
删除最后一名联系人后保存空快照（characters/conversations/messages 均为空，activeCharacterId=null）。刷新不会重新创建默认角色，侧栏保留添加入口；再次导入会建立新的空会话。
只有浏览器首次没有新快照时才执行默认联系人初始化/旧版迁移。人物卡 JSON 格式与稳定 ID 规则未更改。
保存删除结果失败时保留联系人并显示错误；默认联系人删除成功但旧备份清理失败时，会明确显示警告。数据不可读的临时会话不允许删除原数据。

人格卡不控制调度时间；等待时间和输入延后属于应用聊天设置。编辑人物卡不会中断已开始的生成，下一轮使用保存后的版本。Real 发送人格字段和当前会话近期上下文；Mock 仍使用固定测试回复。
