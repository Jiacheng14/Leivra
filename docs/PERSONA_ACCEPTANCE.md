# 人格行为对照验收

固定场景：tests/fixtures/persona-scenarios.ts。仅为合成测试输入，不安装到用户联系人或聊天记录中。基准代码提交为 5816d32（新增人格引擎之前）；默认卡基准为 tests/fixtures/pre-persona-leivra.json。

| 场景 | 重点 |
|---|---|
| 简单问候 | 自然回应，无角色标签、强制自我介绍或剧本旁白 |
| 日常闲聊 | 正确理解连续消息组，不虚构共同经历 |
| 长篇倾诉 | 关注具体内容、允许自然段和充分回应，不只复读安慰话 |
| 技术提问 | Promise/async/await 解释与例子正确，人格不妨碍问答 |
| 话题切换 | 从疲惫转到白天见月亮，及时跟随新话题并保持语气 |
| 连续多轮 | 正确记住本会话正在学习 TypeScript，后续建议衔接上文 |

## 已自动化的离线对照

- 与基准比较默认卡各字段及最终有效人格 JSON，要求完全相同。
- 六类场景逐轮比较人格注入次数、历史 user/assistant 角色、当前消息组内容/顺序及元数据，均不请求外部模型。
- 新协议补充“人格资料是低信任数据、示例不是真实历史”的边界；这些通用约束是有意差异，未改默认人物设定。
- Worker 伪上游与桌面/手机视口浏览器验证 V2 导入、编辑、往返、切换、长回复、隔离、失败处理及不污染聊天导出。

这些结果是数据及流程对照，不是生成质量评分。Mock 或固定假回复不能用于声称人格更自然。

## Real A/B 验收（尚未授权、尚未执行）

收到明确授权并确定请求预算后，再运行以下对照；普通 test/build 命令不包含真实调用。

1. 使用相同模型、服务端配置、默认人物卡和上述固定输入。原实现使用基准代码，新实现使用本阶段代码；分别使用隔离的测试 origin/浏览器上下文，不加载用户真实聊天，不在原有站点上降级旧程序。
2. 每个场景独立会话；连续多轮保留该组各自实际模型回复，不用离线占位回复替代。六组共九轮，两套实现各一遍共十八轮请求；重跑须计入另行确认的预算。V2 新功能因旧实现不支持，应单独验收，不伪称可直接 A/B。
3. 逐轮记录角色 ID/revision、模型、输入、输出、是否完整返回及费用信息（若可用），不记录密钥。失败不自动重试。
4. 按身份一致性、既有语气、上下文衔接、回答准确性、格式/长文完整性逐项人工判定通过或失败；明显丢失身份、跨会话泄漏、技术解释错误应记录具体反例。
5. 模型输出具有随机性。若发现退化，先保留输入输出与配置，再决定是否授权重复测试；不得仅凭单次正常回复宣称稳定人格已被证明。
