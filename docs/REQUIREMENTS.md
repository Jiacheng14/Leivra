# 功能需求与验收

## 本阶段已实现
| 需求 | 验收方式 |
|---|---|
| 响应式聊天 | 桌面显示侧栏，360/390/412px 无横向溢出；输入区可见 |
| 消息交互 | 用户在右、角色在左；显示头像、时间和日期分隔 |
| 输入 | 空白不发送、最多 2000 字符、生成和派发期间仍可连续发送；中文输入法确认不误发送 |
| 模拟回复 | 明确标注模拟；收集完成才生成，生成/派发期间显示输入状态和独立回复气泡 |
| 滚动 | 在底部跟随新消息；向上阅读时不强拉到底部，可点击回到最新 |
| 持久化 | IndexedDB 完整保存各角色记录；空记录不重新生成欢迎语；损坏存储显示提示 |
| 主题 | 浅色、深色可切换，刷新保持选择 |
| 数据操作 | IndexedDB 完整持久化；版本化 JSON 完整备份与确认后替换恢复；清空需确认 |
| PWA | 生产构建生成 manifest、图标与 SW；安装后离线可打开本地模拟应用 |

## 验证边界
浏览器自动化使用桌面 Chromium 和移动视口。Android 实机软键盘、系统导航栏、安装入口与独立窗口行为仍需实机验收，不能等同为已完成。

## 已确定的后续需求
后端保管密钥；正式云端数据必须私有；加入身份验证与用户数据导出、删除。
长期目标：真实模型、长期记忆、主动消息和推送、扩展角色管理、语音；群聊仅为远期可能方向，本阶段不实现。

## 待讨论
身份验证方式、单用户还是多用户；模型/预算；记忆范围与保留期限；主动消息频率和免打扰；语音方案。当前不进行实现。
## 人格解耦阶段（2026-10-27）
- 已实现 Character、Conversation、Message、Memory、ModelProvider 接口；所有会话/消息按稳定 characterId 关联。
- 人物卡 v1 校验、默认卡、导入/导出、编辑与 revision；重复 ID 和未知版本报错，失败不覆盖已有数据。
- Prompt Builder 按协议、人物、授权共享信息、角色记忆、最近上下文、当前消息排序；通用协议固定，其他角色的数据排除。
- 设置提供当前卡编辑/导出；侧栏统一提供联系人选择、添加及删除。聊天布局与主题保留。
- 旧消息迁移默认角色并保留原始 ID/时间；更名保留关联，角色切换不取消原会话，清空取消目标会话任务。
- Memory 只有版本化接口；共享信息和记忆未在当前发送流程启用，分别传空数组。
- 人格阶段完成时未接 API；本次已实现本机 API 适配，真实凭据调用尚未验收；仍不提取长期记忆、不做群聊/推送/语音或正式云环境。


## 联系人管理验收
- 侧栏标题为「联系人」，列表显示头像、名称与明确选中态。
- 添加支持 Leivra v1 与 Character Card V2 JSON，复用校验；设置不重复选择/导入入口。
- 每个删除入口先确认范围，取消/Escape 不改数据；确认取消回复，按 ID 级联删除该卡、会话和消息。
- 删除非当前联系人保持选择；删除当前联系人切换剩余联系人；删除最后一名后刷新仍为空，添加入口可用，不重建默认联系人。
- 手机按钮打开同一联系人侧栏，切换/添加/删除均可操作，窄屏无横向溢出。

## 自然聊天与本机 API 验收（2026-10-27）
- 连续三条消息仅触发一轮生成，独立保留 ID、内容、顺序和时间；新消息重置最后发送截止时间。
- 回复等待设置默认 5 秒、范围 1–60 秒、滑条步长 1 秒，刷新持久化；已有半秒设置继续兼容。最大等待设置默认 5 分钟、范围 1–10 分钟、步长 0.5，或选择“不限”。输入延后默认关闭；开启后，最后一次输入活动也按所设等待时间计时。有限最大等待从本轮第一条已发送消息起计算，草稿不入请求。
- 每会话 Idle/Collecting/Generating/Dispatching 独立运作；生成/派发时的新消息排入下一轮，同会话无并发、无重复显示，角色间不串上下文。
- 支持单条短文、多条短文、单条长文及长短混合，换行和自然段原样显示；不按字数或标点机械拆分。
- 第一条立即显示，后续按 min(4,1+sqrt(字符数/50)) 秒派发；异常大输出明确报错，不能静默截断。
- 刷新恢复收集队列及剩余气泡；中断的生成只允许手动重试；切换生成来源不自动提交旧队列。模式切换提示可忽略目标会话的待回复任务，消息保留并显示红色感叹号，后续请求上下文排除这些消息；保存失败不得视为忽略成功。
- Mock 与 Real 共用管理器、调度、提示词、输出验证、消息结构及持久化。Mock 不调用网络模型，Real 失败不静默降级。
- 后端独占密钥，模型通过配置指定；请求限制、超时、并发/频率控制、身份密钥/配额/限流/网络等错误均有伪造响应测试。
- 真实模型验收待用户配置密钥并显式发送测试消息；自动化通过不代表已连接真实 OpenAI。
- UI 仅增加两项聊天设置、必要失败重试及准确的 Real 隐私说明，不改人物卡格式或蕾芙菈人格，不新增视觉设计。


## Persona Engine 第一阶段（2026-10-28）

- V2 JSON 数据兼容；保留未知字段、世界书与扩展，编辑支持字段不得破坏源卡数据。不是完整 V2 执行语义兼容。
- 单一 PersonaRenderer 负责身份、性格、语气、关系、场景和示例数据；固定应用协议优先，外部卡不获得 system 权限。
- Worker 独立校验快照并重建请求；不接受浏览器指定的协议或已渲染 sections。
- 默认人格文本及 v1 有效人格上下文精确保持，已存人物卡不受默认 JSON 迁移影响。
- 保持现有模式、调度、消息角色、恢复与持久化边界。六类场景的真实回复对照待用户授权，不自动发起付费请求。

## IndexedDB 与本地备份（2026-10-29）

- IndexedDB 为唯一实时写入来源；首次迁移有效 localStorage 快照并保留原件，迁移失败不得显示空白历史作为成功结果。
- 完整保存人物卡、会话、全部消息、设置与调度状态；事务完成前不得报告保存成功或发起依赖本次状态的请求。
- Web Locks 保持单页写入所有权；结果未知的生成在刷新或恢复后不得自动重发。
- 设置中导出版本化 JSON；恢复前验证并展示概要，用户确认后原子替换，恢复前快照可回滚。无效文件和不兼容版本不得覆盖数据。
- 备份不含凭证，包含私人聊天内容；支持时申请浏览器持久存储，仍需用户自行保存备份。
- 数据读取失败时所有普通修改均被拒绝；从备份恢复不受普通初始化失败限制。
- 导入历史备份的待生成任务需手动重试，刷新不解除暂停；恢复期间禁止其他修改，恢复前快照可导出并经确认重新导入。
- 保存失败后可以安全重试消息及未保存气泡；异步发送完成不得清除随后输入的草稿或重复提交同一草稿。
