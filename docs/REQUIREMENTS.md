# 功能需求与验收

## 本阶段已实现
| 需求 | 验收方式 |
|---|---|
| 响应式聊天 | 桌面显示侧栏，360/390/412px 无横向溢出；输入区可见 |
| 消息交互 | 用户在右、角色在左；显示头像、时间和日期分隔 |
| 输入 | 空白不发送、最多 2000 字符、等待回复时不重复发送；中文输入法确认不误发送 |
| 模拟回复 | 明确标注模拟；发送后出现输入状态和独立回复气泡 |
| 滚动 | 在底部跟随新消息；向上阅读时不强拉到底部，可点击回到最新 |
| 持久化 | 刷新保留最近 500 条；空记录不重新生成欢迎语；损坏存储显示提示 |
| 主题 | 浅色、深色可切换，刷新保持选择 |
| 数据操作 | JSON 导出；清空需确认且取消未完成回复 |
| PWA | 生产构建生成 manifest、图标与 SW；安装后离线可打开本地模拟应用 |

## 验证边界
浏览器自动化使用桌面 Chromium 和移动视口。Android 实机软键盘、系统导航栏、安装入口与独立窗口行为仍需实机验收，不能等同为已完成。

## 已确定的后续需求
后端保管密钥；正式云端数据必须私有；加入身份验证与用户数据导出、删除。
长期目标：真实模型、独立气泡、长期记忆、主动消息和推送、角色管理、语音。

## 待讨论
身份验证方式、单用户还是多用户；模型/预算；记忆范围与保留期限；主动消息频率和免打扰；语音方案。当前不进行实现。
